# 개발 서버 접속 안내

우리 팀의 코드 저장소와 이슈 트래커는 사내 서버에서 운영합니다.
인터넷에 공개되어 있지 않고, **Tailscale이라는 VPN에 연결된 사람만** 접속할 수 있습니다.

| 서비스 | 주소 | 용도 |
|---|---|---|
| **Gitea** | `http://forge.tail025553.ts.net:3000` | 코드 저장소 (Git) |
| **Plane** | `http://forge.tail025553.ts.net:8080` | 이슈 · 프로젝트 관리 |

> **주소는 반드시 위 전체 주소를 쓰세요.** `forge` 같은 짧은 이름은 동작하지 않습니다.
> 즐겨찾기에 등록해 두시면 편합니다.

전체 소요 시간은 **약 15분**이며, 3단계입니다.

---

## 1단계 — Tailscale 설치 및 초대 수락 (5분)

### 1-1. 설치

<https://tailscale.com/download> 에서 본인 OS용 설치

- **Windows / macOS**: 설치 후 실행하면 트레이(메뉴바)에 아이콘이 생깁니다
- **iOS / Android**: 앱스토어에서 "Tailscale" 검색

### 1-2. 계정 만들기

Tailscale을 실행하고 **Log in** → Google · GitHub · Microsoft 계정 중 편한 것으로 로그인합니다.
**무료이며 별도 결제가 없습니다.**

> 회사 계정으로 이미 다른 Tailscale 조직에 소속되어 있다면 초대 수락이 막힐 수 있습니다.
> 그 경우 **개인 계정으로 따로 가입**해 주세요.

### 1-3. 초대 수락

관리자가 보낸 **초대 메일의 링크**를 열고 **Accept** 를 누릅니다.
수락하면 본인 Tailscale에 `forge.tail025553.ts.net` 서버가 추가됩니다.

### 1-4. 확인

Tailscale이 **연결됨(Connected)** 상태인지 확인한 뒤, 브라우저에서 접속해 보세요.

```
http://forge.tail025553.ts.net:3000
```

Gitea 로그인 화면이 뜨면 성공입니다.

> **접속이 안 될 때 가장 흔한 원인은 Tailscale이 꺼져 있는 것입니다.**
> 트레이 아이콘을 확인하고 연결 상태로 바꿔 주세요.
> 서버를 쓰는 동안에는 Tailscale이 계속 켜져 있어야 합니다.

## 4단계 — Git 사용 준비 (개발자만)

### 4-1. Git LFS 설치 — **필수**

우리 저장소는 이미지·모델·사운드 등 대용량 파일을 **Git LFS**로 관리합니다.
**LFS 없이 clone하면 파일 대신 텍스트 조각만 받아집니다.**

```bash
# Windows: Git for Windows 설치 시 함께 설치됩니다
# macOS:
brew install git-lfs

# 설치 후 1회만 실행 (모든 OS 공통)
git lfs install
```

### 4-2. 저장소 받기

**방법 A — HTTPS (간단, 처음이라면 이쪽)**

```bash
git clone http://forge.tail025553.ts.net:3000/blueigloo/development.git
```

사용자명과 비밀번호를 물으면 Gitea 계정 정보를 입력합니다.
매번 묻는 게 번거로우면 **액세스 토큰**을 만들어 비밀번호 대신 쓰세요:
`설정 → 애플리케이션 → 액세스 토큰 생성`

**방법 B — SSH (키 등록 후 비밀번호 불필요)**

```bash
# 1) 키가 없다면 생성
ssh-keygen -t ed25519 -C "본인이메일"

# 2) 공개키 내용 복사
cat ~/.ssh/id_ed25519.pub

# 3) Gitea 설정 → SSH/GPG 키 → 키 추가 에 붙여넣기
#    http://forge.tail025553.ts.net:3000/user/settings/keys

# 4) clone (포트 2222 주의)
git clone ssh://git@forge.tail025553.ts.net:2222/blueigloo/development.git
```

### 4-3. 주요 저장소

| 저장소 | 내용 |
|---|---|
| `blueigloo/development` | 개발 본체 |
| `blueigloo/resources` | 리소스 · 에셋 |

## 꼭 알아두실 것

### 매일 새벽 5시 서버 점검
매일 **05:00~05:10** 서버가 자동으로 백업 후 재부팅합니다. 이 시간에는 접속이 잠시 끊깁니다.
**이 시간대에 걸치는 긴 작업(대용량 push, CI 빌드)은 피해 주세요.**

### 대용량 파일은 반드시 LFS로
한 번에 **512MB를 넘는 push는 서버가 거부**합니다. 서버 메모리를 보호하기 위한 제한입니다.
새 종류의 바이너리 파일(예: `.psd`, `.fbx`)을 추가할 때는 `.gitattributes`에 LFS 규칙이 있는지 먼저 확인하세요.

```bash
# 현재 LFS로 관리되는 확장자 확인
git lfs track
```

규칙 없이 큰 파일을 커밋하면 나중에 되돌리기가 매우 번거롭습니다. **커밋 전에 확인**해 주세요.

### 외부에서도 그대로 접속됩니다
Tailscale만 켜져 있으면 집·카페·외부 어디서든 동일하게 접속됩니다. 사무실 네트워크일 필요가 없습니다.

### 보안
이 서버는 인터넷에 공개되어 있지 않습니다. **Tailscale 계정과 Gitea 계정을 다른 사람과 공유하지 마세요.**
퇴사·프로젝트 이탈 시 관리자가 접근 권한을 회수합니다.

| Gitea 로그인 실패 | 관리자 승인이 끝났는지 |

| 새벽에 접속 안 됨 | 05:00~05:10 점검 시간인지 |

해결되지 않으면 관리자에게 **어떤 화면에서 어떤 메시지가 나왔는지** 알려주세요.

# 부록 — 관리자용

> 이 절은 팀원에게 전달할 필요 없습니다.

## 신규 인원 온보딩 순서

1. **Tailscale 노드 공유**
   admin console → Machines → `forge` → ⋯ → Share → **Share by email** 탭 → 이메일 입력 → Share
   - **Copy invite link의 Reusable link는 쓰지 말 것** (최대 1,000회 재사용 가능 = 유출 시 누구나 진입)
   - 미수락 초대는 **30일 후 만료** → 재발송 필요

2. **Gitea 가입 승인**
   `http://forge.tail025553.ts.net:3000/-/admin/users` → 비활성 계정 편집 → 활성화
   (`REGISTER_MANUAL_CONFIRM = true` 이므로 승인 전에는 로그인 불가)

3. **Gitea 권한 부여**
   `blueigloo` 조직에 팀 멤버로 추가

4. **Plane 워크스페이스 초대**
   워크스페이스 설정 → Members → 초대
   - **SMTP가 설정되어 있지 않아 초대 메일은 발송되지 않습니다.** 초대 자체는 DB에 기록되므로,
     팀원이 같은 이메일로 로그인하면 대기 중인 초대가 보입니다.

## 이탈자 처리

1. Tailscale: Machines → `forge` → Share → 해당 사용자 ⋯ → **Revoke invite** (즉시 차단)
2. Gitea: 관리자 → 사용자 → 비활성화 또는 삭제
3. Plane: 워크스페이스 멤버에서 제거

**1번만 해도 네트워크 접근은 즉시 끊깁니다.** 나머지는 정리 차원입니다.

## 접근 통제 구조

- 네트워크 계층: Tailscale ACL이 공유 사용자를 **`3000`, `2222`, `8080` 세 포트로만** 제한
  - 관리자 SSH(22)는 공유 사용자에게 열려 있지 않음
  - 개인별 차등은 불가(`autogroup:shared`로 일괄) → **권한 구분은 Gitea/Plane 계정에서**
